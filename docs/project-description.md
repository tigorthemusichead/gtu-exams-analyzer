Описание работы системы
Клиентское приложение преподавателя

Клиентское приложение студента
В начале экзамена студент авторизуется в приложении по университетской почте (в идеале может быть интеграция с e learning или vici), выбирает экзамен / контрольную, которую будет писать, номер группы, вариант
Выбирает директорию / папку, в которой будет работать, в этой папке инициализируется git
Начинается отслеживание изменений файлов в данной папке (раз в N секунд git diff, git add, git commit). Git diff покажет изменения (дельту) за период времени в N секунд
Для каждого файла, в котором произошло изменение отправляется запрос на backend сервер системы со следующими данными
commit_id, student_id, timestamp, exercise_id, lines_added, lines_removed, file_name
Завершив работу студент либо завершает работу клиентского приложения, либо выключает ПК

Серверное приложение
Авторизация и аутентификация
Авторизует студента: получает электронный адрес, номер группы, айди экзамена и вариант, в ответ отдает JWT токен (валидный в течение 1 - 2х часов в зависимости от типа экзамена), хранящий в себе айди пользователя, айди экзамена, роль: студент

Авторизованный студент может работать над экзаменом, завершить активную сессию

Авторизует преподавателя: получает электронный адрес и пароль, в ответ отдает JWT токен, хранящий в себе айди пользователя, роль: преподаватель

Авторизованный преподаватель может создавать экзамен, запрашивать обработку данных по выбранному экзамену (созданному им), запрашивать отчет по обработанным данным

Создание экзамена
Преподаватель создает экзамен: название экзамена, номер группы, дата экзамена

Участие в экзамене
Студент авторизуется, выбирает рабочую папку, начинает работать
С заданной периодичностью на сервер отправляются данные commit_id, student_id, timestamp, exercise_id, lines_added, lines_removed, file_name для каждого измененного файла
Закончив экзамен студент завершает работу приложения
Анализ работ
После завершения экзамена преподаватель выбирает экзамен среди созданных им экзаменов (в интерфейсе явно разделяются старые экзамены, по которым уже сгенерированы отчеты и новые экзамены, по которым еще нет)
Для каждого отдельного студента:
Анализируется нормальность последовательности коммитов: поиск таких паттернов как появление большого объема кода за неправдоподобно малый промежуток времени, начало работы близко к завершению работы (при условии, что в начале экзамена студент не работал)

Для группы:
Поиск серии последовательных коммитов у разных студентов

Поиск семантически близких коммитов: для близких по времени коммитов также вычисляется косинусная близость или другие метрики близости текстов

Структурный анализ близких коммитов: для близких по времени коммитов определяется структурная близость за счет классификации по именам функций, переменных, стилю комментариев

На базе этих метрик вычисляется общая метрика уверенности в факте копирования решений между коммитами. Также эти метрики могут быть рассчитаны и на полном коде. Назовем ее M

Строятся графы, содержащие информацию о студентах, потенциально списавших друг у друга. Мощностью ребра графа считается сумма метрики M для всех пар последовательных коммитов студентов.

Отчет:
На базе анализа отдельных студентов и группы создается отчет, содержащий полный список студентов с метрикой нормальности последовательности коммитов. Система предлагает пороговое значение, после которого студенты попадают в подозреваемую группу

Отображается интерактивный граф близости между работами студентов, при клике на ребро графа открывается окно с детальными метриками. Также визуально выделяются ребра, для которых метрика близости M больше порогового значения

Отображается саммари со списком подозреваемых студентов
